# PDF 요약 앱 설계 (summary4pdf)

작성일: 2026-11-19
개정: 2026-11-19 (설계 검토 반영)
상태: 승인 대기

## 1. 무엇을 왜 만드는가

PDF 파일을 올리면 AI가 한국어로 요약해 주는 웹앱이다.
강의 7장 7.5~7.6절의 실습 결과물이며, 교수 저장소 `logistex/summary4pdf-ch7`
(배포: `summary4pdf-ch7.vercel.app`, 마지막 태그 `PDF_04_01`)과 같은 성격의 앱을
직접 만들어 보는 것이 목적이다.

왜 지금인가: 7장 과제이기 때문이다.

성공의 모습: 배포 주소에 PDF를 올리면 몇십 초 안에 한국어 요약이 화면에 뜬다.
실패하면 왜 실패했는지가 화면에 그대로 보인다.

**결과가 교수 저장소와 똑같을 필요는 없다.** 노션 7.7절이 "결과가 영상과 달라도
됨. 노트의 '이렇게 확인'에 적힌 것이 되면 그 단계는 끝난 것임"이라고 밝혔다.
교수 저장소는 베껴 쓸 대상이 아니라 다 만든 뒤 견줘 볼 참고물이다.

## 2. 목표 / 비목표 / 반(反)목표

### 목표
- PDF 업로드 → 한국어 요약 4종 출력
  1. 한 문장 요약
  2. 핵심 개념 3~5개
  3. 문서가 **직접 정의한** 용어
  4. 문서가 **직접 정의한** 수식
- 업로드 파일과 요약 결과를 서버에 저장하지 않는다
- 1차 모델이 실패하면 폴백 모델로 한 번 더 시도한다
- Vercel에 배포하고, 배포된 주소에서 동작을 확인한다
- 7.6절 성찰: 평가 보고서와 개선 규칙을 남긴다

### 비목표
- 로그인, 사용자별 보관함, 요약 이력 (7.4절 다이어리 앱의 영역이다)
- 스캔 PDF(글자가 이미지로 들어 있는 문서) 지원 — OCR은 범위 밖
- PDF 외 형식(docx, pptx, 이미지)
- 여러 파일 동시 업로드
- 교수 저장소와 파일 이름·구조를 일치시키는 것

### 반목표 (이렇게 되면 기술적으로 돌아가도 실패다)
- **실패를 성공처럼 보이는 것.** 모델 호출이 실패했는데 빈 요약이나 지어낸
  요약이 뜨면 안 된다. `D:\6주차` CLAUDE.md가 정한 규칙을 그대로 잇는다.
  플랫폼이 함수를 강제 종료해 응답이 아예 안 와도 마찬가지다(§5.7).
- **API 키가 브라우저로 새는 것.** 키는 서버에서만 쓴다.
- **올린 파일이 서버에 남는 것.**
- 요약이 잘린 사실을 숨기는 것

## 3. 제약

- **Node.js 26.13.1 LTS 설치 완료** (2026-11-19, winget). npm 11.20.0.
  winget에 Node 24가 더는 없어 최신 LTS인 26을 깔았다. Next.js 16은 Node
  20.9 이상이면 동작한다. 26에서 문제가 생기면 nvm-windows로 24를 따로 깐다.
  → 구현·테스트·실행 검증이 모두 가능하다. 눈 감고 짜는 계획은 필요 없다.
- 이미 떠 있는 터미널은 PATH가 낡아 `node`를 못 찾는다. 앱을 새로 띄우거나
  명령 앞에 PATH를 다시 읽히면 된다.
- OpenRouter 키는 사용자가 이미 보유 중이다(`D:\6주차\.env`). 새 프로젝트
  `.env`에는 **사용자가 직접** 복사해 넣는다. 코드가 키를 찍거나 커밋하면 안 된다.
- 무료 모델은 수시로 막히거나 사라진다. 모델 이름을 코드에 박지 않는다.
- Vercel 무료 플랜의 함수 실행 시간 — 요약 API `maxDuration` 120초, Fluid
  compute 필요. 이 예산 안에 들어가도록 제한시간을 잡았다(§5.5).
- OpenRouter 개인정보 설정에서 무료 모델 사용을 허용해야 한다. 안 하면 404가 난다.

## 4. 검토한 방법들

### A. Next.js 16 (App Router) + TypeScript + Vercel ← **채택**
서버 라우트에서 OpenRouter를 부르므로 키가 브라우저에 노출되지 않는다.
7.5절이 정한 구성과 같아 강의 흐름(배포·태그·성찰)을 그대로 따라갈 수 있다.

### B. Python + Streamlit
이미 깔린 Python으로 바로 시작할 수 있고 6주차와 같은 방식이라 익숙하다.
하지만 7.5절의 결과물(Vercel + Next.js)과 다른 물건이 되어 과제 대조가 안 된다.

### C. 브라우저 단일 HTML + 사용자 키 입력
설치가 없고 GitHub Pages로 바로 배포된다. 그러나 키가 브라우저에 노출되어
반목표를 정면으로 어긴다. 버렸다.

**사용자가 A를 골랐다.**

### 5.4 서버 API
`POST /api/summarize`, `multipart/form-data`, 필드 `file`

성공 200:
```json
{
  "성공": true,
  "한줄요약": "…",
  "핵심개념": [{ "이름": "…", "설명": "…" }],
  "정의된용어": [{ "용어": "…", "뜻": "…" }],
  "정의된수식": [{ "수식": "…", "뜻": "…" }],
  "쓴모델": "nvidia/…:free",
  "글자수": 82431,
  "쓴글자수": 40000,
  "잘림": true
}
```

실패 200 (HTTP 오류가 아니라 본문으로 알린다 — 화면이 시도 기록을 그려야 하므로):
```json
{
  "성공": false,
  "까닭": "모든 모델이 실패했습니다",
  "시도기록": [
    { "모델": "nvidia/…:free", "결과": "HTTP 429" },
    { "모델": "nvidia/…:free", "결과": "시간 초과(50초)" }
  ]
}
```

요청 자체가 잘못된 경우(파일 없음, 4MB 초과, PDF 아님, 글자 0자)는 400으로
돌려보내고 `까닭`에 한국어 설명을 넣는다.

`정의된수식`과 `정의된용어`는 **빈 배열이 정상**이다. 검증기는 빈 배열을
실패로 보지 않는다. `한줄요약`이 비었거나 `핵심개념`이 0개일 때만 실패로 치고
폴백으로 넘어간다.

### 5.5 모델 설정
코드에 모델 이름을 박지 않는다. `.env`로 바꾼다.

| 변수 | 뜻 | 기본값 |
|---|---|---|
| `OPENROUTER_API_KEY` | 키 (사용자가 직접 넣음) | — |
| `OPENROUTER_MODEL` | 1차 모델 | `nvidia/nemotron-3-ultra-550b-a55b:free` |
| `OPENROUTER_FALLBACK_MODEL` | 폴백 모델 | 비움 — §5.9 점검 스크립트로 고른다 |
| `OPENROUTER_TIMEOUT_MS` | 1차 제한시간 | `40000` |
| `OPENROUTER_FALLBACK_TIMEOUT_MS` | 폴백 제한시간 | `50000` |
| `MAX_CHARS` | 모델에 보낼 최대 글자수 | `40000` |

폴백은 **한 번만** 돈다. 1차가 HTTP 오류·시간 초과·빈 응답·JSON 깨짐 중
무엇으로 실패하든 똑같이 폴백으로 넘어간다.

**폴백은 1차와 다른 회사 모델로 고른다** (설계자 판단). 둘 다 같은 회사
무료 모델이면 회사 단위 429나 무료 티어 폐지 때 1차와 폴백이 한꺼번에
죽는다 — 6주차에서 겪은 바로 그 실패다. 지금 어떤 무료 모델이 살아 있는지는
계정마다 다르므로, `.env.example`에는 폴백을 비워 두고 §5.9 점검 스크립트가
실제로 쓸 수 있는 모델을 알려주면 그때 채운다.

**제한시간 예산** — 40초 + 50초 = 90초. 업로드·글자 추출·검증에 쓸 여유가
30초 남아 Vercel의 120초 안에 들어간다.

### 5.6 한계값
- 파일 크기 4MB 초과 → 400
- 추출 글자가 `MAX_CHARS`(기본 40,000) 초과 → 앞부분만 쓰고 `잘림: true`로 알린다
  - 교수 저장소는 60,000자지만, 40,000자(대략 13,000~20,000토큰)로 낮춰 잡았다.
    무료 모델은 문맥 창이 작은 것이 많아 60,000자면 길이 때문에 매번 실패할 수 있다.
    §5.9 점검 스크립트가 고른 모델의 문맥 창을 알려주므로 그에 맞춰 올리면 된다.
- 추출 글자 0자 → "글자가 없는 PDF입니다(스캔 문서는 지원하지 않습니다)" 400

### 5.7 플랫폼이 함수를 끊는 경우 (설계자 판단)
Fluid compute가 꺼져 있거나 한도를 넘기면 함수가 강제 종료되어 **응답 본문이
아예 오지 않는다.** 이때도 반목표를 지켜야 하므로, 브라우저가 자체 시계를
갖는다.

- 브라우저는 `AbortController`로 115초에 요청을 끊는다
- 끊기거나 응답이 JSON이 아니면, 서버가 준 것처럼 꾸미지 않고
  "서버가 응답하지 않았습니다 (115초 초과) — Vercel의 Fluid compute가 켜져
  있는지 확인해 보세요"라는 별도 실패 화면을 띄운다
- 이 화면은 시도 기록 대신 '서버 무응답'이라고 분명히 적는다

### 5.8 화면이 모델 이름을 아는 방법 (설계자 판단)
모델 이름은 서버 환경변수에만 있다. 진행 중 화면에 모델 이름을 띄우려면
설정 조회용 엔드포인트를 더 두거나 스트리밍으로 API 모양을 바꿔야 한다.
**둘 다 하지 않는다.** 진행 중에는 모델 이름 없는 일반 진행 표시만 띄우고,
모델 이름은 끝난 뒤 응답에 담겨 오는 `쓴모델`과 `시도기록`에서만 보여준다.
API는 요청 한 번에 응답 한 번인 단순한 모양을 유지한다.

### 5.9 비밀과 점검 (설계자 판단)
- 키는 서버 환경변수로만 읽는다. 로그에 키와 요청 헤더를 찍지 않는다
- `.env`는 `.gitignore`에 넣고 `.env.example`만 커밋한다
- 6주차의 `scripts/install-hooks.sh`(커밋 전 비밀 차단)를 같은 방식으로 가져온다
- 업로드 파일은 메모리에서만 다루고 디스크에 쓰지 않는다
- 서버 로그는 `[summarize]`로 시작하는 줄만 남긴다
- **`scripts/check-openrouter.mjs`** — 6주차 `scripts/test_openrouter.py`에
  해당하는 점검 도구. 가짜 서버로 하는 Vitest는 실제 모델 ID가 살아 있는지
  증명하지 못하므로 따로 둔다. 하는 일:
  1. OpenRouter `/api/v1/models`에서 무료 모델 목록과 각 문맥 창 크기를 받아온다
  2. `.env`의 1차·폴백 모델이 그 목록에 있는지 확인한다
  3. 짧은 글로 실제 호출을 한 번 해 본다
  4. 문맥 창에 비춰 `MAX_CHARS`가 적절한지 알려준다

  키가 필요하므로 **사용자가 직접 실행한다**(`npm run check:or`).

### 5.10 코드 작성 규칙 (설계자 판단)
`D:\6주차`를 보니 **파일 이름은 영어, 문서와 주석은 한국어**로 쓰고 계신다
(`llm.py`, `vision.py`, `recipe.py`). 그 방식을 따른다.

- 파일·폴더 이름: 영어. 한글 경로는 Node 도구들이 가끔 탈이 난다
- 주석, 문서, 화면 글, 커밋 메시지: 한국어
- 직접 만든 함수·변수명: 한국어 (`요약하기`, `글자뽑기`, `모델호출`)
- 프레임워크가 정한 이름은 그대로 (`page.tsx`, `route.ts`, `POST`, `useState`)
- 파일은 UTF-8

## 9. 구현하며 설계와 달라진 것

구현 중 사양과 어긋난 곳을 여기 적는다. 자세한 까닭은 ledger의 `Ruling:` 줄에 있다.

1. **React 컴포넌트 이름만 영어 PascalCase** (`Home`, `Block`, `SummaryView`).
   eslint `react-hooks/rules-of-hooks`가 컴포넌트 이름의 첫 글자가 대문자이기를
   요구하는데 한글에는 대문자가 없다. §5.10의 "프레임워크가 정한 이름은 그대로"에
   해당한다. 안쪽 함수는 한국어 그대로다.
2. **라우트에 `export const runtime = "nodejs"`를 적지 않는다.** Next 16의
   `cacheComponents`와 함께 쓸 수 없다고 빌드가 거부한다. nodejs가 기본값이라
   동작은 같다.
3. **`설정읽기`의 매개변수 타입이 `Record<string, string|undefined>`다.**
   `NodeJS.ProcessEnv`는 `NODE_ENV`를 요구해 시험에서 작은 객체를 넘길 수 없었다.
4. **라우트가 `설정읽기`를 `글자뽑기`보다 먼저 부른다.** `글자뽑기`가 설정의
   `최대글자수`를 받아야 하기 때문이다. 계획이 적은 순서가 틀렸다.
5. **Node 26.13 LTS를 쓴다.** winget에 24가 없었다. Next.js 16은 20.9 이상이면 된다.
6. **`@types/node`를 26으로 올렸다.** 뼈대가 깐 20이 vitest 5와 충돌했다.
7. **시험용 PDF 내용이 라틴 문자다.** pdf-lib 기본 글꼴이 한글을 못 그린다.
   한글 PDF에서 글자가 제대로 뽑히는지는 **배포 뒤 사용자가 실제 문서로 확인해야 한다.**

### 전체 코드 검토 뒤 고친 것 (PDF_03_02 성격)

8. **§5.4의 실패 기준을 글자 그대로 지키게 고쳤다.** `정의된용어`·`정의된수식` 칸이
   어긋나도 어긋난 항목만 버리고 요약은 살린다. 전에는 통째로 버려서, 폴백이 비어
   있는 초기 상태에서 곧바로 전체 실패가 됐다. `핵심개념`은 그대로 엄격하다.
9. **JSON 후보를 여러 개 시도한다.** 울타리가 여럿이면(모델이 지시문의 형식 블록을
   복창한 뒤 답하는 흔한 경우) 검증을 통과하는 첫 것을 쓴다. 전에는 첫 울타리만 보고
   복창본을 파싱해 실패했다.
10. **시도 기록의 폴백 모델명에 `(폴백)`을 붙인다.** §5.3이 약속한 표시가 빠져 있었다.
11. **`OPENROUTER_BASE_URL` 환경변수를 더했다.** 보통 비워 둔다. 가짜 서버로 **200 성공
    본문**(쓴모델·글자수·쓴글자수·잘림)을 라우트 수준에서 시험하려고 뺐다. Pre-flight
    Ruling이 "작업 6에서 확인한다"고 적어 놓고 하지 않은 확인을 이걸로 닫았다.
12. **요약 중에는 드롭을 받지 않고, 요청마다 번호를 둔다.** 전에는 요약 중 다른 파일을
    고르면 앞 파일의 요약이 새 파일 이름 아래 떴다. 브라우저로 재현하고 고친 뒤 다시
    확인했다.
13. **JSON이 아닌 응답(Vercel 504) 경로에도 '서버 무응답'과 Fluid compute 안내를 붙였다.**
    다만 "115초 초과"라고는 적지 않는다 — 빨리 온 응답에 그렇게 쓰면 거짓이 된다.
14. `.claude/launch.json`을 지웠다(깨진 JSON에 절대 경로). `check:or`를
    `--env-file-if-exists`로 바꿔 `.env` 없이도 한국어 안내가 나오게 했다.
    `next dev`가 다시 만드는 `AGENTS.md`를 `.gitignore`에 넣었다.

## 10. 설계 검토에서 고친 것

문서 초안을 다른 개발자 시점으로 검토받아 아래를 고쳤다.

1. Node가 없다는 제약이 해소됨 — 뼈대를 손으로 쓸 필요가 없어졌다 (§3, §5.1)
2. `정의된수식`이 화면에만 있고 API 스키마에 빠져 있었다 — 추가 (§5.4)
3. 빈 배열을 실패로 오해할 여지 — 검증 기준을 명시 (§5.4)
4. 1차·폴백이 같은 회사 무료 모델이면 동시에 죽는다 — 다른 회사로 (§5.5)
5. 60,000자가 무료 모델 문맥 창을 넘길 수 있다 — 40,000자로 낮추고 설정화 (§5.6)
6. 45+60초가 120초 예산에 빠듯했다 — 40+50초로 (§5.5)
7. 함수가 강제 종료되면 응답이 없다 — 브라우저 자체 시계와 별도 실패 화면 (§5.7)
8. 진행 중 화면의 모델 이름 표시가 API 모양을 바꿔야 했다 — 표시하지 않기로 (§5.8)
9. 실제 모델 ID가 사는지 확인할 길이 없었다 — 점검 스크립트 추가 (§5.9)
10. 한글 파일명이 6주차 방식과 달랐다 — 영어 파일명으로 (§5.10, §5.11)
11. `PDF_04_01` 태그가 빠져 있었다 — 7.6절 성찰로 추가 (§5.12)
12. 교수 저장소와 파일 단위로 같아야 하는지 — 아님을 명시 (§1, §2)
